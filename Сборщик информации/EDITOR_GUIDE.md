# Локальный кабинет редактора

## Запуск

Команды выполняются из папки `Сборщик информации`. Нужен Python 3.11+.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-lock.txt
python -m app doctor
python -m app web --open
```

Адрес кабинета: <http://127.0.0.1:8765>. Сервер работает, пока открыт процесс Python; остановка — Ctrl+C. Альтернативный порт: `python -m app web --port 8766`. Сервер принимает только подключения с этого компьютера. Интернет нужен для явно запрошенного сбора и проверки ссылок; просмотр очереди, редактирование, диагностика и экспорт работают локально.

Необязательная удобная команда устанавливается из этой же папки: `python -m pip install -e .`. Затем можно выполнять `sborschik web`. Это редактируемая установка из исходного checkout: храните рядом исходный реестр `../sources.yaml` либо задайте `SOURCES_FILE`.

## Очередь и проверки

1. На странице «Обзор» выполните «Собрать материалы». Источники без включённого RSS/API добавляются через «Материалы → Добавить вручную». Частичный отказ источника отображается отдельно от успешного сбора.
2. Создайте сводку за 24, 48 или 96 часов. Если локальная семантическая модель не установлена, материалы останутся отдельными; возможные повторы нужно проверить редактору.
3. В карточке сводки откройте источник каждого утверждения, прочитайте его и сохраните краткое основание проверки ссылки. Кабинет повторит HTTP-проверку; доступность URL сама по себе не подтверждает факт. Редакторская отметка действует 24 часа.
4. Укажите дату события и её основание. Если дата неизвестна, исключите пункт. Во вкладке «Группы» сохраните отдельные решения о тождестве события и независимости источников.
5. Рассмотрите предупреждения об обновлениях источника. Можно сохранить прежнюю версию с объяснением либо обновить утверждение и выполнить проверки заново. Предыдущие версии остаются в истории.
6. Во вкладке «Текст поста» отредактируйте сводку и сохраните. Кнопка «Убрать служебные подсказки» удаляет только известные технические инструкции; утверждения, ссылки и даты остаются. Сохранение изменений сбрасывает редакторские отметки ссылок, дат и групп: удобнее сначала подготовить текст, затем выполнить финальные проверки. Предпросмотр справа показывает Markdown; перед отправкой проверьте сохранённый текст. Лимит — 4000 символов.
7. Выберите одну часть дневной партии. Одобрите конкретную версию сводки, подтвердив выполненные проверки. Для дальнейшей редактуры используйте «Вернуть на проверку».
8. «Проверить отправку» запускает тот же контроль без обращения к MAX и без чтения токена. «Опубликовать в MAX» требует отдельного подтверждения редактора в интерфейсе. За московский календарный день разрешён один основной пост. Исправления связаны с исходной публикацией и не занимают этот слот.

Если другой процесс изменил сводку, устаревшее решение не сохраняется: обновите карточку и повторно проверьте изменения. Одобрение связано с версией текста и основаниями, а журнал решения сохраняется в той же транзакции.

## Предпросмотр и экспорт

В карточке доступны TXT (точный сохранённый текст), HTML (текст и таблица оснований) и JSON (структурированные утверждения, проверки, версии и попытки отправки). HTML-экспорт не исполняет разметку источников. Экспорт отражает состояние на момент создания и не является свидетельством отправки в MAX.

Из терминала:

```powershell
python -m app export 1 --format html --output data/exports/draft-1.html
python -m app export 1 --format json --output data/exports/draft-1.json
python -m app review edit 1 --text-file data/edited-post.txt
python -m app review reopen 1
```

Экспорт не перезаписывает существующие файлы.

## Резервное копирование и восстановление

Во вкладке «Диагностика» нажмите «Создать резервную копию». Копия SQLite и манифест сохраняются в каталоге `backups` рядом с рабочей базой. Копия включает подтверждённые записи WAL, исходные материалы, историю, решения и очередь. Учётные данные Windows и переменные окружения в базу не копируются. Вместе с копией отдельно сохраняйте свой `sources.yaml` и код приложения; манифест не заменяет их.

```powershell
python -m app backup create
python -m app backup create --output data/backups/manual.sqlite3
python -m app backup verify data/backups/manual.sqlite3
python -m app backup restore data/backups/manual.sqlite3 --to data/recovered/app.sqlite3
```

Храните `.sqlite3` и соответствующий `.sqlite3.manifest.json` вместе. Проверяются SHA-256 файла, схема, `integrity_check` и внешние ключи. Восстановление разрешено только в новый файл, отличный от текущей рабочей базы; перезапись исключена. После восстановления проверьте результат через `doctor`, прежде чем использовать его для работы.

Для отдельного runtime задайте абсолютный путь **до запуска Python**:

```powershell
$env:APP_DATA_DIR = "C:\EditorialRuntime\recovered"
$env:SOURCES_FILE = "C:\EditorialConfig\sources.yaml"
python -m app doctor --json
python -m app web
```

При обновлении старой схемы существующая база автоматически сохраняется до миграции. Повторные подключения к актуальной схеме не создают новые копии. Если резервное копирование не удалось, миграция не начинается.

## Диагностика

`python -m app doctor --json` возвращает `ok`, `warning` или `error` и список отдельных проверок. Код возврата при `error` — 1, иначе 0. Команда не выполняет миграции, не создаёт базу, не загружает модель и не обращается к MAX или источникам. Проверяются схема и целостность SQLite, конфигурация, возможность записи runtime, зависимости, наличие локальных файлов модели и незавершённые отправки. Наличие токена показывается только логическим признаком; доступ к живому API не проверяется.

Отсутствие необязательной модели и ненастроенный MAX дают предупреждение: локальная редактура доступна. После первого запуска `web` создаётся пустая рабочая база.

## Неопределённый результат отправки

После обрыва связи приложение сохраняет `unknown` и блокирует повтор. Откройте канал и установите фактический результат, затем используйте действие «Указать результат проверки» или `publish-resolve`. Для опубликованного поста нужна действительная ссылка MAX.

Попытку `started` нельзя освобождать, пока процесс-отправитель работает. Для восстановления после аварии остановите этот процесс/сервер и дождитесь истечения пятиминутного резерва, затем проверьте канал. Старые попытки без владельца тоже требуют истечения резерва. Не повторяйте отправку до выяснения результата.

## Проверки разработки

```powershell
python -m unittest discover -s tests -v
node --check app/static/app.js
```

Основной набор использует временные SQLite и подменённые HTTP-ответы: живые источники и MAX не вызываются, модель не скачивается. Необязательная проверка реальной модели описана в основном README. GitHub Actions проверяет Python 3.11/3.12 на Windows и Linux; результат локального запуска не заменяет результата удалённого CI.
